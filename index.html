01 / 为什么需要它

媒体业务的
三类共性问题

上传、转码、播放和保护是音视频项目的共性环节。PowerMedia 将这些能力整合为可独立部署的服务，减少重复建设。

01

上线等待长

大文件上传后通常需要等待完整转码，课程、会议录像和直播素材难以及时上线，影响观看体验与内容发布效率。

02

资源成本高

对所有片源无差别转码、缓存和存储，而多数内容长期无人访问，会持续浪费算力与存储空间。

03

内容保护难

拿到地址就能播放、链接被随意转发，课程与内部资料一旦外流，损失难以挽回，事后也缺少审计依据。

02 / 核心能力

围绕播放主链路的四项核心能力

围绕“上传到播放”主链路组织功能，分别改善上线效率、资源成本、内容安全与多语种体验。

A

即传即播

上传完成的文件无需等待整片转码：播放请求到达时按需生成切片与清单，边生成边播放。首次播放走 JIT 通道，重复播放直接命中缓存，不再启动转码。

冷启动 < 3 s · 热态 < 1 s
B

智能预热

按热度与资源状况挑选候选片源，异步生成切片并写入与播放共用的缓存。资源紧张时自动降速或暂停，优先保障在线播放，避免与播放任务争抢算力。

四档门控 · 不占即时通道
C

私有加密

支持 Widevine、FairPlay、PowerDRM 与 HLS AES-128，内置许可证服务。播放需通过短期令牌与密钥授权，直接复制文件或转发地址均无法播放。

密钥 15 分钟过期
D

多音轨 · 多字幕

音轨预提取生成多音轨 HLS，自动识别内嵌字幕与 Sidecar 文件，PGS 图形字幕通过 OCR 还原，语音内容可转写并翻译，一个片源服务多语种观众。

zh-CN / zh-TW / en / ja / ko
03 / 能力矩阵

从入库到分发，一条链路都覆盖

各能力可独立启用，也可按需接入现有系统。

01

媒体库与元数据

电影、剧集、动漫、音乐、图片、文档统一入库，多路径多库管理，各类型均有对应的浏览、播放或阅读界面。

  • 元数据刮削：TMDB、TVDB、豆瓣、Bangumi、OMDb，字段缺失时由 AI 辅助补全
  • 剧集模型：季 / 集结构、特别篇、多版本同片归并
  • 库级权限：多角色、库级 ACL、家长控制（分级 + PIN + 时段）
02

播放引擎

直链 MP4、HLS、DASH 自适应，JIT 按需切片；多播放器引擎自动切换，兼容不同终端内核。

  • 进度同步：跨端续播、播放历史与收藏
  • 预览雪碧图：进度条缩略图 + WebVTT 时间线，扫描期预捕获海报
  • 多音轨：音轨预提取，master playlist 内自由切换
03

转码与调度

按需转码、预转码优化与集群调度协同工作，根据资源水位决定任务启动、降速或暂缓。

  • 集群编排：local / 数据库 / Redis 三种调度方案，跨节点清晰度并行
  • 资源调度器：容量预留、队列声明、准入决策可解释、老化与库公平
  • 任务控制面：统一概览与钻取、批量操作、审计变更
04

内容保护

DRM 打包与许可证服务一体化，加密媒体同样可以安全分享，链接可设口令与有效期。

  • 多方案 DRM：Widevine、FairPlay、PowerDRM、HLS AES-128
  • 分享管控：匿名链接、访问口令、有效期、嵌入代码、访问审计
  • 静态加密：落盘即加密，断点续传不破坏加密会话
05

智能分析

把非结构化媒体变成可检索的资产：人脸、地点、场景分类，文档 OCR 与版面还原。

  • 照片管理：人脸聚类、地理分布、场景分类
  • 字幕与转写：Whisper ASR，LLM 校对，多语翻译
  • 文档阅读：OCR、版面还原、电子书在线阅读
06

平台与集成

既能独立部署，也能作为媒体微服务嵌进现有平台，通过 REST API 与 OAuth 客户端对接。

  • 多数据库：SQLite、PostgreSQL、MySQL、达梦 DM8、金仓 KingbaseES
  • 接口鉴权：JWT、OAuth 客户端凭证、Bearer / Query Token 双模式
  • 交付形态：内嵌部署 → Docker → 分布式 Redis 集群
04 / 引擎如何工作

一条主链路，五个可观测的环节

每个环节均提供状态、进度与失败恢复信息，便于运维排查。

STEP 01

入库与扫描

多路径扫描、文件监控、持久化摄入队列，崩溃后可恢复认领。

STEP 02

识别与刮削

解析容器与轨道信息，补齐元数据与海报，生成预览雪碧图。

STEP 03

预热与转码

按热度挑选候选，异步生成多清晰度切片；资源紧张自动让路。

STEP 04

打包与加密

HLS / DASH 打包，DRM 或 AES-128 加密，密钥与许可证分离管理。

STEP 05

分发与播放

清单与切片经缓存分发，播放凭短期令牌鉴权，行为可审计。

资源门控：优先保障播放

预热任务按实时水位在四档间迁移：OPEN 空闲时放行（CPU 可用 ≥ 30%）， THROTTLE 紧张时降速（CPU ≥ 70% 降至 1/4）， PAUSE 告急时立即暂停（≥ 85%）， RESUME 恢复需连续 5 分钟达标、每 60 秒只加 1 个并发。 在播请求永远优先，预热只使用剩余容量。

缓存生命周期：按需保留，到期回收

切片缓存与播放共用同一套键，不存在第二套预热缓存； 闲置 7 天沉降、30 天硬上限回收、删除保留 24 小时软删宽限， 元数据一致窗口 5 秒。命中率仅统计“鉴权通过的切片请求”，避免重复请求放大指标。
